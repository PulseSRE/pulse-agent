Finds what broke. Asks before it fixes it.

Pulse Agent is an SRE and security agent for OpenShift, built on Claude. It watches your cluster, traces each incident to the change that caused it, and only acts on what you approve. Then it waits to see whether the fix held.

Every fix goes through four steps

Nothing skips a step. A fix that is not verified does not count, and Pulse does not learn from it.

  1. Notice

    32 scanners check the cluster every minute, from crashlooping pods to expiring certificates and SLO burn. If one lacks a permission, Pulse says so and how to fix it, instead of showing an empty list.

  2. Explain

    It ranks what changed before the incident (rollouts, ConfigMap edits, Argo CD syncs, cluster upgrades) and shows the evidence, the alternatives it ruled out, and a confidence score.

  3. Ask

    Every change waits for your approval, with the exact target named. The approval carries a one-time code, so it cannot be replayed. Ask only for a plan and no change is offered at all.

  4. Verify

    After a fix, Pulse watches the finding. Only a fix that holds for the recurrence window, 30 minutes by default, counts as verified, and only verified fixes teach it anything.

What's new

v2.34.022 October 2026
Pairs with UI v2.34.0 and operator v0.11.0

  • Tighter security boundary. Only admins can use the tools that change the agent itself. Metrics queried from chat run with your permissions, not the agent's. Secret values are redacted before anything reaches the model.
  • Chat survives API trouble. Rate limits and dropped connections are retried, and one failed turn no longer breaks the rest of the conversation. Cut-off answers say so.
  • Approvals reach people. A durable plan waiting on approval becomes an inbox item you can answer there, instead of only from the panel that started it.
  • Pod logs show the end. The agent reads the most recent log lines, where a crash is, instead of startup noise.

What it will not do on its own

These are enforced in code and server settings, not in the prompt, and nothing in the browser can loosen them.

Write to your cluster

Read-only unless the operator enables writes. At the default trust level, every change asks first. The server sets the highest trust level; the browser cannot raise it.

Act with more power than you have

Chat requests run with your own OpenShift token, so Pulse can only do what you are allowed to do. The monitor's background scans use the agent's own service account.

Delete pods in protected namespaces

production, openshift-* and kube-system by default. Configurable.

Drain or cordon nodes

Off unless an admin turns on the break-glass setting.

Count a fix it has not seen hold

A fix is only verified once the finding stays resolved. Before an automatic fix changes a resource, Pulse keeps a restorable copy of it.

Run it on your cluster

Pulse needs OpenShift 4.12 or later and a Claude backend: Vertex AI or an Anthropic API key. The operator installs the agent, the UI and PostgreSQL from one resource.

# After installing the operator from its catalog
apiVersion: pulse.ai/v1alpha1
kind: OpenShiftPulse
metadata:
  name: pulse
  namespace: openshiftpulse
spec:
  vertexAI: { projectId: my-gcp-project, region: us-east5, credentialSecret: gcp-sa-key }
  agent: { image: quay.io/amobrem/pulse-agent:v2.34.0, trustLevel: 2 }
  ui:    { image: quay.io/amobrem/openshiftpulse:v2.34.0 }
